# Changelog

All notable changes to TimeTiles are documented here. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

See the [release process](/development/contributing/release-process) for how new versions are cut.

## [Unreleased]

Changes landed on `main` since the last tagged release.

## [0.1.0-alpha.17] - 2026-09-29

### Fixed

- Import: CSV preview, schema detection, row count and import read a file the same way — a leading byte order mark, blank lines before the header, duplicate or padded header names and delimited `.txt` files no longer make them disagree
- Import: valid UTF-8 files are no longer misread as a single-byte charset, so `Köln` stays `Köln`
- Import: counting rows of a missing sheet or an unsupported file type fails instead of reporting zero, and duplicates written in place under the `update` strategy are no longer reported as skipped
- Login: overlapping logins of one account no longer drop each other's session, and expired sessions are removed on login
- Explore: a zoom or pan made before the map style loads is kept, and a map view from the URL is no longer replaced by the fit to the data
- Explore: the map reports itself busy until its clusters match the view, and the theme picker no longer shifts the header while the page loads
- API: `/api/v1/sources/stats` counts events of public datasets whose catalog was deleted in `totalEvents`
- API: `/api/legal-notices` and dataset schema inference report failures instead of answering with empty notices or "not found"
- Development: `validate-types` checks Payload's generated files without rewriting them or leaving backups

### Security

- A catalog made public, or a dataset moved to a public catalog, only in a draft no longer makes its events public before the change is published
- Approving an import job no longer applies field-mapping changes to a dataset the approver cannot edit

## [0.1.0-alpha.16] - 2026-09-28

**Upgrade note:** the scraper runner no longer defaults its work area to `/tmp/timescrape` and refuses to start without an absolute `SCRAPER_DATA_DIR`. Bootstrap step 13 writes it into the runner's systemd unit. `timetiles update` leaves a runner whose unit predates this in place and names the step to rerun: `sudo deployment/bootstrap/bootstrap.sh --step 13-scraper-setup`.

### Changed

- Cache: the general cache keeps only its filesystem backend; the cleanup job fails, and is retried, when cleanup or statistics fail instead of reporting invented numbers
- Scrapers: the reported row count skips a record holding one empty field, as the import does

### Fixed

- Scrapers: CSV rows are counted per record, so quoted fields spanning lines or containing literal quotes no longer skew the count
- Scrapers: the Node and Python SDKs refuse rows without fields instead of writing an empty file
- Scrapers: runs whose output the watchdog cannot read are killed, and the reason names the path
- Scrapers: output download and cleanup errors are reported instead of answering 404 or staying silent
- Scrapers: a clone whose repository size cannot be read fails instead of passing the size limit
- Scrapers: the run's stderr names the signal that ended podman
- Scrapers: the runner rejects empty or out-of-range settings at startup, and `init` rejects unknown arguments
- CLI and bootstrap: the runner is swapped by renames, so an old install that cannot be deleted is still replaced as a whole
- CLI and bootstrap: `.env` lines with CRLF endings are read without the carriage return

### Security

- Scrapers: repository clones refuse a git host the SSRF check cannot resolve

## [0.1.0-alpha.15] - 2026-09-28

### Fixed

- CLI: `update` finishes in a fresh process after pulling the deployment files, also with `--no-self-update`, so the rest of the update runs the pulled CLI with the pulled libraries

## [0.1.0-alpha.14] - 2026-09-28

### Changed

- Ingest: uploads accept one shared MIME allow-list; the Google Sheets type is gone because no parser reads it
- CLI and bootstrap: runner install, podman calls and `.env` reads share one implementation; bootstrap replaces the runner atomically, so a failed install keeps the old one
- CLI and bootstrap: `.env` values containing `=` or quotes are read whole; a repeated key takes its last assignment

### Fixed

- Scrapers: an invalid cron expression disables the scraper and marks the run failed instead of skipping it silently forever
- Ingest and seeding: lookup errors other than "not found" are raised instead of treated as a missing record
- CLI: a failed image pull shows the registry error before falling back to a local build; a failing alert script is reported as a warning

### Security

- URL fetches and scraper repo sync refuse the request when the SSRF DNS check cannot resolve the host, instead of skipping the check

## [0.1.0-alpha.13] - 2026-09-28

### Fixed

- CLI: a root invocation keeps `TIMETILES_DISCARD_CONTAINER_DB` when it hands over to the deploy user, so the "Database Outside the Volume" reset works under `sudo`
- CLI: `create-admin` without a terminal fails with a message naming `TIMETILES_ADMIN_PASSWORD` instead of exiting silently
- File cache: `destroy()` waits for the index write and reports its errors instead of dropping them
- CMS blocks: list items are keyed by their Payload id

### Security

- Ingest: transform expressions use `expr-eval-fork`, which rejects prototype access such as `constructor` and `__proto__` (CVE-2025-12735, CVE-2025-13204)

## [0.1.0-alpha.12] - 2026-09-28

### Fixed

- Bootstrap: steps run from `/`, so podman invoked as the app user no longer aborts on an inherited working directory it cannot enter
- Bootstrap: the scraper-setup step restarts the runner, so a rerun applies the rewritten systemd unit instead of leaving the old one active

## [0.1.0-alpha.10] - 2026-09-28

A large hardening release covering deployment, background jobs, ingest, the URL cache and access control. Production compose now runs one worker per job queue, and only the web container runs migrations. Imports into the same dataset now run one at a time. **Upgrade note:** the postgres cluster now lives in the `postgres_data` volume (kartoza `DATADIR`). On installs created before this release, the database sits in the container's writable layer, and `timetiles up`/`down`/`restart`/`update` refuse to run. Take a backup first, then follow "Database Outside the Volume" in `deployment/README.md`.

### Added

- `timetiles create-admin <email>` creates the first admin on a fresh install. It takes the password from the environment, skips email verification, and refuses to change an existing account. Bootstrap now prints next steps that point to it
- New deployment settings: `INGEST_FILE_RETENTION_HOURS` / `INGEST_FILE_ORPHAN_GRACE_HOURS` (import working-file cleanup), `TRUSTED_PROXY_CIDRS` (client IP for rate limiting behind a proxy), `DOCKER_NETWORK_SUBNET` (pinned bridge subnet that the scraper-runner firewall rule relies on) and `EXPORT_HOST_DIR` (shared data-export directory)
- Scrapers: owner-scoped repository sync status, with sync errors shown in the UI
- Development: `make setup-mac` provisions a macOS machine (including the h3 extension), and `PG_LOCAL_PORT` sets the local PostgreSQL port

### Changed

- Database: the postgres data directory is now `/var/lib/postgresql/data` inside the `postgres_data` volume. Lifecycle commands guard against installs whose database is outside the volume, and `TIMETILES_DISCARD_CONTAINER_DB=1` overrides the guard
- Version history is capped at 10 versions per event and 5 per ingest job. Media no longer keeps drafts or versions
- Imports: imports into one dataset are serialized with a Postgres advisory-lock lease, while different datasets still import in parallel. A failed update-strategy import rolls back fully, including sheet imports
- Deployment: `worker-general`, `worker-ingest` and `worker-maintenance` each consume their own queue, and exactly one of them handles schedules. The workers wait for web to finish migrating. The all-in-one image now runs background jobs and logs nginx to stdout. Updates pull deployment files from the pinned release tag
- The map uses maplibre-gl v6 with its worker served from the app, so the CSP no longer allows blob workers
- Ingest-created catalogs, datasets and events are published on creation. Draft catalogs, datasets, events, footers and menus are hidden from public and non-owner reads
- Generated slugs transliterate umlauts and accents, and stored slugs no longer change on save. Feature flags apply as soon as settings are saved
- Accessibility and i18n: map control popovers are keyboard accessible, closed filter surfaces leave the tab order, result changes and form errors are announced, the date slider moves by whole days, and dates, chart labels and remaining UI strings follow the app locale (EN/DE)

### Removed

- The `HOST_PORT` and `CONTAINER_PORT` deployment variables. The app port is fixed at 3000, and changing `CONTAINER_PORT` used to deadlock the stack
- The placeholder `EMAIL_SMTP_HOST` in the env template. Leave it unset to run without outgoing mail
- npm from the production runtime image, and ineffective schedule-retry and job-timeout settings

### Security

- Access control: closed IDOR holes, XSS sinks, fail-open query and H3 filters, and a catalog-delete grant leak. Clients can no longer write credential, derived-access, pipeline, scraper run-state or scheduler fields. Native job controls and user creation are restricted to admins, and ingest-job updates to editors and admins
- Auth: password policy enforced and sessions revoked on reset, credentials revoked on deactivation, cancel-deletion attempts rate-limited, and rate-limit keys namespaced with the client IP taken only from trusted proxies
- SSRF and redirects: closed the IPv4-mapped IPv6 bypass and redirect targets that smuggle a host past the prefix check. Bracketed IPv6 clone hosts are classified correctly
- Data leaks: user data is escaped in emails, 5xx responses and export emails no longer expose internal errors, logs no longer contain URLs, OAuth, cache or provider details, or subscriber emails, and persisted cache keys hash their source URLs. Exports no longer strand personal data, and account deletion serializes with export publication
- CSV downloads are formula-escaped at the download boundary, including handling for delimiters, BOM, `sep=` and SYLK. Stored ingest data is left unchanged
- Scraper sandbox: runner containers are bounded, rootless Podman egress is fenced by the app user's uid, the seccomp profile ships, and run output is read without following symlinks

### Fixed

- Deployment and backup: four containers no longer migrate one database at once, and quoting `/etc/timetiles.env` protects passwords with spaces or backticks. A failed runner is detected and kept on a bad update, and a failed offsite backup alerts. `restore latest` picks the newest snapshots and swaps uploads in atomically. Also fixed: a certbot anonymous-volume leak, and nginx static asset locations that dropped security headers
- Ingest and schema: source encoding is detected and phantom blank rows are dropped. EU decimals, timed dates and multiline CSV headers parse correctly. Excel previews match imported column names. Pagination limits and OAuth, token and custom-header auth configs are validated. Cron and DST schedule edge cases (nonexistent midnight, leap days, empty timezones) are handled. Retries and manual triggers are queued in the claim transaction. Stale mappings are cleared, and data-package activation parameters are validated
- Jobs and cleanup: stuck-ingest wedging, quota rollback and an audit transaction leak are fixed. Partial cleanup failures (exports, previews, ingest files, audit IPs, schema maintenance) are retried. Processing and restarted jobs are kept out of cleanup. A scraper run that never started refunds its quota
- Scrapers: run timeouts use kill escalation and keep partial logs. Leftover work directories are swept. Deleting a scraper while a run is active is refused, and a duplicate active run id returns 409. Schedules stop after deactivation, and cron syntax is validated before saving
- URL cache: honors Vary, quoted and mixed-case cache-control, zero TTL and mandatory revalidation. Partial responses are kept out of the cache, the persisted index is validated, and cleanup runs in the ingest worker
- Geocoding: provider calls abort on timeout, backoff and throttles are respected, disabled fallback and provider groups are honored in batches, Photon gateway failures are retried, and the kill switch no longer fails open when settings cannot be read
- Explore, charts and events: histogram buckets cover ranges beyond 68 years, and a UTC session allows pre-1900 timestamps. Trashed events are hidden from SQL read paths and counts. Invalid numeric ranges in shared URLs are rejected. Event titles render through the dataset field mapping. Dark-mode chart theme and map label halo are fixed
- Accounts: account deletion scheduling, cancellation and execution are serialized, all due accounts are processed, and verification and reset state is isolated per token

## [0.1.0-alpha.9] - 2026-06-30

A large stabilization release. Five multi-agent bug sweeps across correctness, security, privacy, internationalization, and ingest/scraper robustness, plus ICU pluralization and localization of the remaining hardcoded copy. Closes the interpretation follow-ups from alpha.7 and hardens the production image build.

### Added

- Background job that reclaims and sweeps orphaned ingest CSV files
- `timetiles check` verifies cron and systemd path references

### Changed

- Count strings use ICU plurals; page metadata, account-deletion copy, and remaining hardcoded strings localized (EN/DE)
- Draft preview restricted to content roles (admin/editor); draft content is no longer served to anonymous visitors

### Fixed

- Security and privacy: drop all credential headers on cross-origin redirect; isolate the URL-fetch cache by auth identity; cap quota-remaining to block privileged-account enumeration; close a private-event leak in the H3 cluster branches; pair the pinned SSRF dispatcher with undici fetch (and stop it blocking public `fd*`/`fc*` domains); add `X-Frame-Options` and `frame-ancestors` CSP; restrict credential reads and rotate sessions on change
- Accounts and auth: allow cancelling a scheduled deletion; defer email swap to verification time to prevent lockout; re-validate deletion eligibility at execution; unbreak email verification and enforce `isActive`; stop faking reset-email success
- Ingest and schema: make dataset-detection idempotent and `findOrCreateDataset` concurrency-safe; prevent duplicate data-package activations under concurrency; reuse the latest schema version when unchanged and persist real enum frequencies; fail oversized imports terminally instead of stranding them; fix re-import data loss and progress/review stalls; numerous import-wizard and edit-schedule state fixes
- Scrapers: recover stuck and orphaned runs; coerce off-contract runner output; RFC 4180 CSV escaping in the SDK writer; handle webhook-queue failures; make scraper deletion (and account-deletion coverage) work
- Maps, charts, and explore: derive H3 resolution from returned cells; fix histogram tooltip dates, bar clicks, and locale; clamp range-slider bounds and keep drags alive with pointer capture; validate explore URL filter params to prevent crashes; apply range and cluster filters consistently across views
- Quota and events: stop double-releasing event quota; pin the daily reset to a UTC boundary; clear the quota claim after a successful create
- Geocoding: apply provider confidence grades correctly; preserve hemisphere for `-0°` DMS coordinates; score by result type and gate bias params
- Deploy and build: pin timescrape's `zod` so the production image builds; thread `DEFAULT_LOCALE` into image builds; ship `health-check.sh` and `alert.sh` as tracked files

## [0.1.0-alpha.7] - 2026-06-03

Introduces a unified row-interpretation pipeline (ADR 0040) that fixes silent data misreads — day/month date order, single-column combined coordinates, and locale-aware numbers — plus numeric range filtering on event fields. Includes two large multi-agent bug sweeps.

### Added

- Numeric range filtering on event fields, with EU-aware decimal and thousands parsing
- Single-column combined coordinates (e.g. `"52.5, 13.4"` in one field), with a review gate for ambiguous axis order
- Per-column date day/month order detection with a review gate, fixing a silent DD/MM vs MM/DD misread
- Locale-aware number parsing during record merge
- Best-effort opt-in for ambiguous interpretations (ADR 0040)

### Changed

- Row interpretation unified into a single persisted interpretation plan — coordinate, date, and number handling now flow through one path (ADR 0040, Phases 0–4)
- Layered-architecture ESLint boundaries now actually enforce the `lib/` layering

### Fixed

- Two multi-agent bug sweeps (a 28-bug sweep and a backend correctness/security/rate-limit sweep): event quota charged only for newly-created events, locale-independent sort keys for dedup and cache, committed sub-batches retained on partial bulk-insert failure, import config validation (ID-strategy and mapping vs transforms), and map labels/antimeridian/single-day timezone/virtualization
- Salvage swapped axis order for ambiguous combined coordinates
- Deploy: writable tmpfs for the Next.js `.next/cache`; scraper returns 409 before 429 on an in-progress run
